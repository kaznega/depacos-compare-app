# デパコス比較アプリ 更新手順書

正本は `master-catalog.json`（全色の機械可読データ）。アプリ（space-4）は正本から生成したスナップショットを内蔵した単体完結ページで、オフラインでも動く。**更新は「正本を直す → アプリへ反映 → ゲート → 共有し直し」の順**。次回以降は差分（新商品・新ライン・色変更）だけを調べればよい。

## 1. 差分の特定
- 対象ブランドの現行ラインを @cosme のブランドページで確認し、正本（master-catalog.json）に無いライン／色、無くなったライン／色を洗い出す。
- 海外名称・日本と異なる色番、色が取れなかった製品は `watchlist.md` に必ず記録（ユーザーの最終確認用。海外名称は将来の海外版で使う）。

## 2. 色の抽出（情報源の優先順位）
### リップ（最優先で塗布見本方式へ移行中）
- **なぜ塗布見本か（確定した原因）**：リップ本体（芯）の表面から採ると、斜めカット面への光の反射と表面層の影響で、実際に塗った膜の色より**白く・冷たく**出る。SUQQU 12 想秘で実証済み（芯由来の旧値 #C9A195 は不採用、公式塗布見本の #CC8470 をユーザーが実機・実物照合で確定）。アプリの描画は「唇に塗った色」として重ねるので、採色も塗った膜の色に合わせるのが正しい。
- 優先順位：**①公式の塗布見本・テクスチャ（スワイプ）画像 → ②販売店・@cosme の塗布見本画像 → ③リップ本体の芯・色面は最終手段**。③で採った色は正本の `source` に「画像由来の目安」と明記し、アプリでも目安と分かる表示にする（値を推測で作らない）。
- 採色方法：スワイプの**中心部を複数点サンプリングして中央値**を取る。反射・端部・ハイライト（明るすぎる画素）は除外する。塗布見本が複数ソースにある色は、**2ソースで照合**してから確定する（SUQQU 12 想秘のやり方を標準とする）。2ソースの差が大きい色・境界の色は確定せず「未確認」として watchlist に記録する。
- **画像種別の判定を先に行う（2026-10-30 第2弾で標準化）**：@cosme のバリエーション画像はライン内でも色ごとに種別が混在する（ボビイ ブラウン クラッシュド リップ カラーで実例）。ライン単位の目視分類に加え、色単位で自動分類（黒ケース画素・金属ケース画素の比率でパックショットを検出）を併用し、スティック／ボトルのパックショットと判定した色は採り直さず目安のままにする。QAシート（実画像＋旧チップ＋新チップ）で全色目視照合し、ケース色を拾っていないか必ず確認する。
- **背面スミア型の登録（2026-10-30 第3弾・Diorで標準化）**：バーム／オイル系ラインでは、同じライン内でも「ケース・ボトルの背面にスミア（塗り伸ばし）やドロップが写るテクスチャ寄りの登録」と「通常のパックショット登録」が色単位で混在する（Dior リップ グロウ／マキシマイザー／グロウ オイルで実例）。スミア／ドロップが写る色だけ、その部分の領域に限定して彩度コア中央値で採る（スティック芯・ボトル液色は採らない）。スティック系ライン（ルージュ ディオール等）は @cosme 画像が全色パックショットで、公式サイトも 403 で取得できないブランドがある（Dior／ジバンシイ）。その場合は無理に採らず「調査済み・見本なし」として watchlist に残す。
- **光沢スワイプの採色**：光沢のあるウェッジ型・ドロップ型スワイプは、単純な中央値ではハイライトに引っ張られて実際より明るく出る（ジバンシイ シアー・ベルベットで実例）。この種別では**彩度コア画素（彩度中央値以上の画素）の中央値**を取り、輝度上下8%トリムを併用する。マット系スワイプは中心部中央値が最適（同ラインで両方式を比較し、QAシートの目視で方式を選ぶ）。
- 進捗はカテゴリ→ブランド→ラインの単位で区切り、watchlist の「塗布見本採り直し進捗」に「照合できた色／見本が無く目安のままの色」の内訳で記録する。
### その他のカテゴリ
1. **@cosme の商品画像**（バリエーション画像）から色面を画素サンプリングするのが基本。アイシャドウ／チーク／ベースも、塗布見本・テクスチャ画像があるものはそちらを優先する（リップの次に同じ優先順位で移行する）。
2. @cosme に無い場合のみ海外小売（百貨店系）の商品画像で補完し、`overseas` フラグと海外発売品バッジを付ける。
- サンプリング規則：色値はスポイト値を一切補正しない（正確性最優先）。ケース・容器の色を拾ったら、芯・パン・塗布面の位置から採り直す。パレットはパン中心を個別に採る（検出→失敗時は実測中心座標）。色面が画像に無いもの（閉じたケースのみ、ボトルの色のみ、複合パレット等）は無理に取らず未収録にして理由を watchlist に書く。
- 抽出後は必ず QA シート（元画像サムネイルと抽出色を並べた画像）でラインごとに目視照合する。

## 2.5 名称仕様（2026-10-30 ユーザー指示で確定）
- **「〇〇風」表記は廃止**。全商品・全色を @cosme／公式の**日本販売名どおりの正式名称**で表示する（カード、A/Bチップ、試着パネル、ステージ、管理表示の全箇所）。理由：正式名称でなければ検索でヒットせず、購入先リンクでの購買につながらない。色はスポイトで採っているので正式名称でよい、というユーザーの判断。
- **記号の混入を正式名称に直す**：@cosme のバリエーション名に付く先頭の `#`（例 `#ハンブルブラグ`、YSL `#213 …`）、色番の後の ` #`（ランコム `232 #透けシュガー` 等）、限定を表す先頭の `★`（ジルスチュアート。名前から外し `limited: true` に移す）、名前末尾の `※…` 注釈（ポール＆ジョー）は、正本・アプリとも取り除く。逆に `モチーフ!` の `!`、`ワッツ ザ ワイファイ?` の `?` のように**正式名称自体に含まれる記号は残す**。ダズルシャドウ リキッドの `(水)(地)(火)(風)` は同名色の識別用サフィックス（@cosme表記）として残す。
- **採色元の表示は名称とは別の出所情報として残す**（「公式の塗布見本から採色」「@cosmeの塗布見本から採色・1ソース」「画像由来の目安」等）。名称に混ぜない。
- **検索仕様**：検索はスペース区切りの**トークンAND照合**。照合先キーには ①ブランド日本語名 ②ブランド別名（英語名・略称・読み。アプリ内 `BRAND_ALIAS`）③ライン名 ④色名（正式名称）⑤色名の原語表記 `orig`（正本の項目として保持。取得できる範囲で入れる。まず M·A·C アイシャドウは米国公式のバリアント一覧で照合済み）⑥色名・ライン名のローマ字読み（カナ→ローマ字変換で自動生成）を含める。クエリ・キーとも正規化（小文字化、全角英数→半角、空白・「・」・「ー」・「.」除去）して表記ゆれを吸収する。「mac omega」「MAC オメガ」「dior 999」のような ブランド名＋色名/色番 で確実にヒットすることが要件。
- 新規収録時は上記の記号クリーニングを適用してから正本に入れる。`orig` が公式等で確認できる色は入れる（推測で作らない）。

## 3. 正本への反映
- `master-catalog.json` の records に追加・修正する。項目仕様は同ファイル冒頭の `fields` と `affiliate-design.md` を参照。
- 商品画像URL（`img`）と購入先リンク（`buy: {url, kind}`）は任意項目。空ならアプリに出ない。

## 4. アプリへの反映
- 正本の差分を `~/workspace/ts-spaces/space-4/index.html` の CATALOG に反映する（ライン単位の concat 追加が基本形）。
- ブランドを増やすときは BRANDS 配列、リード文、ブランド別注記、定番・人気色の棚（findBy）も更新する。
- 件数を数え直し、正本の `count` とアプリの表示総数（totalCount）が一致することを確認する。

## 5. 提出前ゲート（省略禁止）
- ブランド×カテゴリごとに最低1ケースを、実写サンプル写真へ実際に適用して確認する（適用後画面＋部位の平均色／変化画素で判定）。
- 顔検出は同梱 MediaPipe（assets/mediapipe）→ jsDelivr CDN の順にフォールバックする実装。公開形態で検出できることが前提。
- 確認できなかった範囲は「未確認」と明記して報告する。確認していないものを「確認済み」と言わない。

## 6. 管理ファイルの更新と共有
- `watchlist.md`：未収録・要注意（海外名称、色番相違、目安扱いの色）を追記。
- `brands-master.md`：ブランドの状態（✅収録済み／対象外確定／未収録）を更新。
- ビルド（web_artifacts.exit_build）→ 監査・プローブで最終確認 → 共有リンクを更新して報告する。
- 報告は3点セット：①ブランド／ライン別の収録数 ②取れなかったものと理由 ③海外名称の注意点。
